Expected `site/astro.config.mjs` after Task 1:
```javascript
import { defineConfig } from 'astro/config';
import sitemap from '@astrojs/sitemap';
import vercel from '@astrojs/vercel';

export default defineConfig({
  // REQUIRED by @astrojs/sitemap. Placeholder URL until Phase 6 wires the
  // actual Vercel preview URL. Sitemap uses this for absolute <loc> entries.
  site: 'https://joesbarbershop.vercel.app',
  integrations: [sitemap()],
  adapter: vercel(),       // No-op for static; unlocks Phase 5 Vercel features
  image: {
    layout: 'constrained', // Stable since 5.10 — auto-srcset + sizes
    responsiveStyles: true,
  },
});
```

Key research facts (from 01-RESEARCH.md):
- `@astrojs/vercel` 10.x uses **unified import** — `import vercel from '@astrojs/vercel'` (NOT `/static` or `/serverless` subpaths; those were removed in v8+)
- `@astrojs/sitemap` 3.7.2 always emits `dist/sitemap-index.xml` + `dist/sitemap-0.xml` (never `dist/sitemap.xml`)
- Astro Image is **built-in** — no `@astrojs/image` package install (that's the deprecated pre-3.0 package)
- DO NOT add `output: 'static'` — static is the default in Astro 6; adding it is redundant
- DO NOT add `output: 'server'` — that would flip everything to SSR (Pitfall 6)

| `astro.config.mjs` site: URL → sitemap output | The `site:` value gets baked into every `<loc>` entry in `dist/sitemap-index.xml` and is shipped to crawlers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02-01 | Information Disclosure | `site:` URL placeholder bakes into sitemap | accept | Phase 1 uses `https://joesbarbershop.vercel.app` (best-guess Vercel slug). If the real preview URL differs, sitemap entries will point at a non-existent host until Phase 6 updates `site:`. No PII or secrets — only a URL guess. Phase 6 task explicitly re-points `site:` to the actual preview URL before showcase. |
| T-01-02-02 | Tampering | npm supply chain for `@astrojs/vercel` and `@astrojs/sitemap` | accept | Both are official Astro org packages; npm 11.x verifies registry signatures. Risk is informational. |
| T-01-02-03 | Spoofing | Adapter mode inversion (accidental SSR via `output: 'server'`) | mitigate | Acceptance criteria explicitly check that `output: 'server'` is NOT set and that `.vercel/output/functions/` does not exist after build. SSR mode would silently break the AEO contract (zero-JS-by-default) and add a runtime attack surface. |
