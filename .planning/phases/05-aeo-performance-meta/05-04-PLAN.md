## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Astro.url + Astro.site → canonical URL | Build-time computed from astro.config.mjs `site` + page path |
| Astro.props.title/description → OG + Twitter | Page-supplied; flows through HTML attribute escaping by default |
| import.meta.env.PUBLIC_CLARITY_PROJECT_ID → inline script | Build-time replaced; via `define:vars` rather than string interpolation |
| Page `<Fragment slot="head">` → Base.astro `<slot name="head" />` | Per-page schema components Plan 05 wires |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-10 | Tampering | `og:title` / `og:description` content from page props | accept | Astro's default HTML attribute escaping protects against quote-breaking; no `set:html` used on meta tag values |
| T-05-11 | Information Disclosure | Clarity inline script in dev → polluting prod dashboard | mitigate | `{enableClarity && ...}` template guard — emission requires both `import.meta.env.PROD === true` AND non-empty `clarityId` (RESEARCH Pitfall 7) |
| T-05-12 | Tampering | clarityId injection via PUBLIC_CLARITY_PROJECT_ID env var | mitigate | Value passed via `define:vars` which Astro/Vite escapes at build time; if a malicious value were set the build would fail at IIFE parse time, not at runtime |
| T-05-13 | Information Disclosure | canonical URL computed from `Astro.site` — hardcoded preview URL | accept | When custom domain lands (v1.5), update `astro.config.mjs` `site:` value — single edit; intentional |
</threat_model>
