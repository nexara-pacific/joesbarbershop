**Pre-flight:**
1. `firecrawl --status` — confirm authenticated, credits ≥ 30 remaining (planner verified 4,355 / 5,000 on 2026-05-07; this task's worst-case spend is 6 credits).
2. `mkdir -p .firecrawl` (gitignored per Plan 00 Task 3).

**Scrape Yelp (canonical hyphenated slug per Pitfall 2):**

```bash
firecrawl scrape "https://www.yelp.com/biz/joe-s-barbershop-el-cajon" \
  --only-main-content \
  -o .firecrawl/reviews-yelp.md
```

If output is < 100 lines OR `grep -c '★' .firecrawl/reviews-yelp.md` returns 0, escalate per RESEARCH § Pitfall 7:

```bash
firecrawl scrape "https://www.yelp.com/biz/joe-s-barbershop-el-cajon" \
  --wait-for 3000 --only-main-content \
  -o .firecrawl/reviews-yelp.md
```

If still empty after one more retry at `--wait-for 6000`, mark Yelp as failed and proceed to Google.

**Scrape Google (Maps URL discovery):**

Two paths depending on whether the canonical Maps URL is known:
- (a) `business.json` `sameAs.gbp` is currently a placeholder. Use `firecrawl search` to discover:

```bash
firecrawl search "Joe's Barbershop El Cajon CA" --scrape --limit 3 \
  -o .firecrawl/google-search.json --json
```

Pick the result whose URL matches `maps.google.com` or `google.com/maps` and scrape:

```bash
firecrawl scrape "$URL" --only-main-content -o .firecrawl/reviews-google.md
```

- (b) If search returns no Maps URL, fall back to a constructed search URL:

```bash
firecrawl scrape "https://www.google.com/maps/search/Joe's+Barbershop+El+Cajon+CA" \
  --only-main-content -o .firecrawl/reviews-google.md
```

Same retry escalation as Yelp: empty output → `--wait-for 3000` → `--wait-for 6000` → mark failed.

**Retry budget enforcement (D-10 specifics):** maximum 3 attempts per surface (Google + Yelp = 6 attempts total). After that, fall through to Task 2's fallback path.

**Pass-through:** If at least one surface returned reviews (any `★` glyphs in the output), this task succeeds. Task 2 will extract from whatever was scraped + use placeholder fallback for any failed surface.

**Total surface failure (BOTH empty):** Task 2 takes the D-10 placeholder-only path.

Reference: D-08, D-10 (fallback), RESEARCH § Pattern 7, Pitfall 2 (Yelp slug), Pitfall 7 (escalation).

**Curate reviews.json from scraped output (or fallback):**

Read whichever of `.firecrawl/reviews-{google,yelp}.md` succeeded in Task 1.

Extraction strategy per RESEARCH § Pattern 7:
1. `grep -A 4 '★★★★★' .firecrawl/reviews-yelp.md` to find 5★ blocks.
2. For each block, extract:
   - reviewer name (often a heading or the line preceding the rating block)
   - quote (the body text)
   - date (often "1 month ago" or "Apr 2026" — normalize to "MMM YYYY" if possible; if unavailable use empty string `""`)
3. Format as: `{"name": "Sarah M.", "rating": 5, "quote": "Best $30 haircut in East County.", "source": "Google", "date": "Apr 2026"}`

**Privacy / attribution rule (D-09, D-11):** reviewer name = first name + last initial only (`Sarah M.`, NOT `Sarah Martinez`). If the public surface only shows full name, manually truncate before writing. If only an initial or only a first name, use what's public.

**Curation rule:** select 6–8 5★ quotes total across both platforms. Mix Google + Yelp (target ~50/50 — UI-SPEC § Review Card). Highest-signal quotes first (specific praise > generic praise — e.g., "Best $30 haircut in East County" beats "Great service"). Quote length 50–200 chars max — trim middle ellipsis if needed but preserve meaning; never invent text.

**Anti-fabrication gate (per VALIDATION.md § Manual-Only Verifications):** if you cannot find ≥ 6 real 5★ quotes after Task 1's scrape AND the gap exceeds 2, take the D-10 fallback path — DO NOT make up quotes.
